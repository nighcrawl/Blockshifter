# Query Loop réutilise le contrat Transform existant, pas de nouvelle abstraction Collection Adapter

L'intégration Query Loop (Carousel/Masonry sur `core/post-template`) a été envisagée avec une nouvelle couche d'abstraction ("Collection Adapter" / "Content Source"), pour découpler l'origine de la collection (Gallery, Group, Query Loop) du mode d'affichage. En pratique, `Blockshifter_Transform::render()` traite déjà tout bloc cible de façon générique — racine de l'élément rendu + ses enfants directs — sans jamais connaître le nom du bloc. `core/post-template` rend déjà `<ul>` + un `<li>` par post, une forme structurellement identique à ce que Carousel (racine → `.splide`, enfants → slides) et Masonry (racine → grid, enfants → tuiles) attendent déjà. Ajouter `core/post-template` aux listes de blocs autorisés suffit ; aucune nouvelle abstraction n'a été construite. Alternative rejetée : introduire une interface Collection Adapter formelle, jugée sur-ingénierie tant qu'aucun bloc cible ne casse l'hypothèse "racine + enfants directs".
