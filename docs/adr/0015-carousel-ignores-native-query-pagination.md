# Carousel + Query Pagination native : combinaison non gérée, documentée comme limite connue

Quand Carousel est actif sur un `Post Template`, la présence d'un bloc `Query Pagination` natif dans le même Query Loop n'est ni bloquée, ni masquée, ni spécifiquement testée. Carousel fournit sa propre navigation (slides) ; empiler une pagination de pages par-dessus n'a pas de cas d'usage produit clair, et la pagination "enhanced" (Interactivity API, swap DOM côté client) rendrait de toute façon l'instance Splide obsolète après un changement de page, faute de ré-initialisation. Plutôt que construire une garde (masquer le bloc, avertissement Inspector, désactivation), la combinaison reste simplement non supportée et documentée comme telle. Cohérent avec la décision de ne construire aucun système de pagination Blockshifter en v0.4. Alternative rejetée : masquer/désactiver `Query Pagination` côté rendu quand Carousel est actif — couplage inutile entre deux blocs indépendants pour un cas non prioritaire.
