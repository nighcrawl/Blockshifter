# Carousel Editor Preview en CSS scroll-snap, pas de vrai Splide monté

ADR-0011 montait un vrai Splide sur le DOM réel du bloc, mais seulement quand il n'était pas sélectionné, pour éviter tout conflit avec la réconciliation React. En usage réel, ce compromis se lit mal : l'aperçu Carousel disparaît dès qu'on clique dans le bloc pour l'éditer — exactement le moment où on veut le voir — et redonne l'impression que la fonctionnalité ne marche pas, alors qu'elle fonctionne comme prévu.

Décision : remplacer le montage Splide par un aperçu purement CSS (`flex` + `scroll-snap-type: x mandatory`), posé via `wrapperProps` sur le wrapper du bloc — exactement le même mécanisme que le Module Masonry (`withMasonryPreview`), sans aucune restructuration du DOM. `--blockshifter-carousel-per-page` (calculé depuis `blockshifterConfig.carousel.perPage`, comme `buildSplideOptions` le faisait pour Splide) pilote la largeur des slides via une règle CSS ciblant les enfants directs.

Conséquences assumées : l'aperçu reste visible et défilable même bloc sélectionné (le problème d'origine est résolu), zéro dépendance chargée (Splide et son import dynamique disparaissent entièrement de l'éditeur), zéro risque de conflit React — mais ce n'est plus un vrai Splide : pas de loop, pas de flèches/dots, pas d'autoplay (déjà exclu de l'éditeur). C'est délibérément l'alternative "carousel CSS maison" qu'ADR-0011 avait écartée comme trop infidèle ; le calcul refait ici est qu'un aperçu toujours visible mais moins fidèle vaut mieux qu'un aperçu fidèle mais invisible au moment où l'utilisateur édite.
